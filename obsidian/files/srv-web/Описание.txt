Приложение "Корпоративный блог"
===============================
По заданию нужно было скачать с http://site.greenskills.gs архив tar с corpblog.

Это импортированый контейнер докер. Подробная информация в файле "Docker без интернета"

Вам бы не удалось запустить этот контейнер, т.к. на сервере установлено hardened ядро, а оно не поддерживает докер.
Здесь было 2 варианта: 
1) если есть сеть - скачиваем generic ядро из репозиториев
2) если сети нет - файлы ядра лежали в каталоге /opt/kernel, их нужно было установить apt install ./имя_пакета.deb

Затем удалить старое ядро (опционально): 
uname -a узнать ядро
apt purge "имя_ядра"
sudo update-grub2 обновить загрузчик и перезагрузить. Можно было просто перезагрузить и загрузиться с generic ядра.

После перезагрузки нужно было запустить контейнеры:
Перейти в каталог где размещен файл docker-compose.yml
Подедактировать его, захарденить некоторые параметры (пароль базы и т.д., на усмотрение) и указать ему конфиг апача, в котором вписаны сертифкаты (пример есть в папке).
Сами сертификаты перенести с DC в каталог, который указали в конфиге

Затем выполнить docker-compose up -d

После того как контейнеры поднимутся, нужно было посмотреть их содержимое.
Нужно было импортировать схему базы во внутрь контейнера с базой:
docker exec -i имя_контенера_с_базой mysql -u имя -p пароль blog < 01_schema.sql

Внутри контейнера с веб-приложением размещен бекдор wso.php

Расположен он по пути:
/static/images/areyoubloger.php

Нужно было зайти в контейнер: docker exec -it имя_контейнера_с_приложением bash
и внутри контейнера удалить файл /var/www/html/corpblog/static/images/areyoubloger.php

Погуглив по фразе blog 1.3 exploit можно было понять, что блог содержит rce узявимость.
https://www.exploit-db.com/exploits/50064 
Это нужно было указать в отчете.


Приложение "Fusion CMS"
===============================
По заданию приложение уже размещалось по пути /var/www/html/fusion
Необходимо было составить конфиг nginx и установить базу mariadb.
Конфиг nginx приложен в папке.

Приложение также содержало wso.php переименованный в sh.php, который располагался по пути /var/www/html/fusion/images/error/sh.php.
Сложность состояла в том, что файл невозможно было удалить даже с правами root, т.к. на файле висел атрибут неизменяемости (на уровне файловой системы).
Проверить можно lsattr sh.php.
Необходимо было выполнить команду chattr -i sh.php, т.о. мы снимаем атрибут, а затем rm sh.php удаляем файл.

Рестартуем сервис nginx и заходим на него с DC через бразуер. Далее настраиваем приложение интуитивно через web. (Указываем базу, ставим модули, потом далее далее далее)

Погуглив версию fusion тоже можно было понять, что cms содержит rce узявимость.
https://www.exploit-db.com/exploits/49911
Это нужно было указать в отчете.

Так же в каталоге gsadmin лежал архив с этой CMS без chattr. Можно было распаковать его в соседний каталог /var/www/html/fusion2. Подправить конфиг nginx и развернуть его копию.
